# Alpha Radar V16.3 — Architecture Freeze

這一版的目的不是再堆疊選股規則，而是把既有模型正式分層並凍結架構，避免後續因單一個案反覆修改造成模型漂移。

## 核心決策流程

1. **資料層**：完整日線、月營收、財報、估值、法人、即時報價。
2. **標的選擇**：回答「哪一檔值得持有／追蹤」。短中長線保留原有技術、歷史案例、基本面、籌碼權重。
3. **盤中強度**：回答「今天是否正在轉強」。只看相對大盤、VWAP、量能、盤中位置、買賣壓與流動性；**不再因單日大漲或漲停扣標的分數**。
4. **進場時機**：回答「現在這個價格是否值得買」。ATR 延伸、距突破區、單日漲幅、近漲停、大盤同步大漲、量能過熱等全部集中在 `policy_engine.py`。
5. **市場風險預算**：Bull / Neutral / Bear **不改個股排名**，只調整「預定部位上限」。
6. **持股管理**：保留原有防守價、獲利保護與持股檢視機制。

## 架構凍結規則

- 選股分數與進場分數永久分離。
- 漲停／單日大漲不剔除強勢股；只降低進場分數及部位建議。
- 大盤 regime 不再對 ranking score 加減分。
- 盤中資料只重排已由完整日線模型篩過的候選池，不把未收盤日 K 塞進多年模型。
- 開盤初期即時資料樣本不足，因此盤中權重由低到高逐步成熟；中午以後才接近原本的最大權重。
- 策略高階權重與門檻集中在 `strategy_config.py`；後續原則上只改設定、不散改程式。
- `return_first_model.py` 的底層技術／歷史案例特徵本版凍結，不因單日輸贏調參。

## 主要檔案

- `app.py`：Streamlit 顯示與互動，不放選股規則。
- `strategy_config.py`：唯一高階策略參數中心。
- `radar_service.py`：完整日線候選池、選股與研究資料整合。
- `return_first_model.py`：技術特徵、歷史相似案例與報酬估計。
- `intraday_engine.py`：即時行情與盤中強度重排。
- `policy_engine.py`：買點、追價風險、部位風險預算。
- `market_data.py`：行情／基本面／法人資料與 SQLite 快取。
- `presentation.py`：文字化說明。
- `industry_profile.py`：細產業標籤。
- `trading_calendar.py`：交易日判斷。
- `operational_tools.py`：掃描鎖與錯誤訊息處理。
- `test_architecture.py`：離線架構回歸測試。

## 顯示方式

每檔股票同時顯示：

- **標的分數**：股票本身的相對排名品質。
- **進場分數**：目前價位的風險報酬。
- **追價風險**：低／中／高／極高。
- **部位上限**：相對於你原本預定正常部位的風險預算，不是占總資產比例。
- **操作文字**：例如「買點佳，可分批」、「強勢但不追，等拉回」、「漲停/近漲停：強勢但不追」。

因此允許出現：

> 標的排名第 1、標的分數 92，但進場分數 25、部位上限 0%。

這是刻意設計，不是矛盾。

## 更新速度

V16.3 保留 V16.2 的完整資料量，不以縮減資料換速度：

- 1000 檔候選設定保留。
- 多年技術特徵每檔只建一次，短／中／長三週期共用。
- SQLite 使用 WAL、批次／共用讀取與快取。
- Streamlit 各頁短時間共用同一批即時報價。
- 盤中只更新即時價量並重排，不反覆重建多年模型。

離線效能測試中，三週期共用特徵相較三次分開計算約快 **1.4 倍**（實際部署仍受網路與資料供應商回應速度影響）。

## 部署

1. 將本資料夾所有正式 `.py` 檔與 `requirements.txt` 放到同一個 GitHub repository 根目錄。
2. Streamlit Cloud 主程式指定 `app.py`。
3. `FINMIND_TOKEN` 為選配。沒有 token 時盤中行情會嘗試 TWSE/TPEx MIS fallback；基本面資料依可用來源處理。
4. 券商分點資料預設關閉；若確有 Sponsor 權限再設定環境變數 `ENABLE_BRANCH_FLOW=1`。
5. V16.3 模型版本不同於 V16.2，部署後第一次需按一次完整更新以建立新快照。

## 測試

離線執行：

```bash
python test_architecture.py
```

測試包含：

- 高階權重加總與盤中權重成熟曲線。
- 漲停股可維持強勢排名但不可被判定為理想買點。
- Bull / Bear 不改排名，只改風險預算。
- 盤中強度不再含重複的追價／過熱懲罰。
- UTF-8 中文 UI 字串無 replacement character，避免先前總評亂碼問題。
- 單股完整離線計算流程。
- `run_scan()` 離線整合流程。
- 共用特徵與舊三次計算法結果一致性及速度比較。

詳細結果見 `DEBUG_REPORT_V16_3.md`。
